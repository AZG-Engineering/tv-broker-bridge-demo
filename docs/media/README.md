# Demo media

Marketing and portfolio assets for the demo. Everything runs on `SimBroker` (paper trading, in-process) with fake demo values and secrets generated by `make init`; no real keys, names or account data appear in any file here.

| File | What it shows |
|------|---------------|
| [`demo.gif`](demo.gif) | The README quick start running for about 55 s (1254x872, 0.6 MB): a valid order filled, the same `alert_id` blocked as a duplicate, a risk-gate rejection, a malformed alert rejected with its reason, a wrong secret rejected, `tv-bridge status`, a resting limit order canceled by `tv-bridge kill`, an alert refused while halted, then `tv-bridge resume`. |
| [`demo.mp4`](demo.mp4) | The same recording as H.264 video (0.8 MB), for pages and social posts that do not autoplay GIFs. |
| [`demo.cast`](demo.cast) | The raw [asciinema](https://asciinema.org) v2 recording (100x30 terminal, 35 KB, text only). Play it with `asciinema play docs/media/demo.cast`, or embed it with asciinema-player. |
| [`architecture-light.png`](architecture-light.png) | The README architecture diagram on a white background, 1600 px wide: alert in, auth and validation, kill switch, idempotency, risk gate, order pipeline, SQLite, reconciler, and the broker adapter with SimBroker and Alpaca paper. |
| [`architecture-dark.png`](architecture-dark.png) | The same architecture diagram on a dark background, 1600 px wide. |
| [`order-state-light.png`](order-state-light.png) | The order state machine from [`DESIGN.md`](../DESIGN.md) on a white background, 1600 px wide: every state an order can be in and the events that move it between them. |
| [`order-state-dark.png`](order-state-dark.png) | The same order state diagram on a dark background, 1600 px wide. |
| [`tools/`](tools) | The scripts that produced the files above, so they can be regenerated when the demo changes. |

## How they were made

- **The recording is real.** `tools/demo-session.sh` starts `make run` and executes every command shown against it. Only the *typing* is simulated, so the pacing is readable; the output on screen is what the commands printed.
- **Three small conveniences keep it readable**, all visible on screen or listed here:
  - `send '<json>'` is a thin wrapper around `curl` that POSTs to `/webhook/tradingview` with the secret from `.env` added (never printed) and pretty-prints the reply. The raw `curl` form is in the [README quick start](../../README.md#quick-start-simbroker-about-5-minutes).
  - `tv-bridge status`, `kill` and `resume` are piped through `jq` (visible on screen) to trim long output to the lines that matter. `kill` and `resume` also print a JSON log line, which is why the filter is `.event // .status`.
  - `HEARTBEAT_INTERVAL_S=1` is set (the default is 5), so SimBroker's cancel after `kill` shows up within a second. SimBroker lives inside the server, which cancels working orders on its next heartbeat.
- **The GIF is rendered by `tools/cast_to_gif.py`**, a small pyte + Pillow renderer, because `agg` could not be installed where these were made. Dark theme, DejaVu Sans Mono 20 px. The MP4 is converted from the GIF with `ffmpeg`.
- **The diagrams are rendered by `tools/render-diagrams.mjs`** with real Mermaid 11 in headless Chromium. The source is read straight out of `README.md` and `DESIGN.md`, so the images always match the docs. Only the colours and label wrap width are set by the script.

## Regenerating

Needs a checkout with `make install` and `make init` done, plus `jq`, `ffmpeg` and `asciinema` (2.x).

```bash
python3 -m venv /tmp/media-venv && /tmp/media-venv/bin/pip install asciinema pyte pillow
PATH=/tmp/media-venv/bin:$PATH PYTHON=/tmp/media-venv/bin/python docs/media/tools/record-demo.sh   # cast, gif, mp4

npm install --prefix /tmp/media-node mermaid@11.4.1 playwright-core@1.49.1
MEDIA_NODE_MODULES=/tmp/media-node node docs/media/tools/render-diagrams.mjs                      # the four PNGs
```

The recording script deletes `data/` and `server.log` in the checkout so every run starts from an empty database.
